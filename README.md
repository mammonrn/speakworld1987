# SpeakWorld — Telegram Voice Translation Bot

โครงเริ่มต้นของ Telegram bot ที่เขียนด้วย **Node.js + [Telegraf](https://telegraf.js.org/)**

## เป้าหมายของโปรเจกต์

เป้าหมายสุดท้ายคือบอทที่ทำหน้าที่เป็น **ล่ามเสียงสองทาง**:

1. ผู้ใช้พูดภาษาไทยส่งเป็น voice message เข้ามาใน Telegram
2. บอทถอดเสียงเป็นข้อความ (Speech-to-Text)
3. แปลเป็นภาษาปลายทางที่ผู้ใช้เลือก — **คาซัค / อังกฤษ / จีน / พม่า / เวียดนาม**
4. เมื่ออีกฝ่ายตอบกลับมาด้วยภาษานั้น บอทจะ **แปลกลับเป็นไทยอัตโนมัติ**

## สถาปัตยกรรม

บอทใช้ผู้ให้บริการภายนอกสามส่วน แยกหน้าที่กันชัดเจน:

| งาน | ผู้ให้บริการ | ใช้ key |
| --- | --- | --- |
| ถอดเสียง (STT) ทุกภาษา | Google Cloud Speech-to-Text (`v1/speech:recognize`) | `GOOGLE_API_KEY` |
| แปล **คาซัค / พม่า / เวียดนาม** | Google Cloud Translation v2 | `GOOGLE_API_KEY` |
| แปล **จีน / อังกฤษ** | OpenAI chat completion (`gpt-4o-mini`) | `OPENAI_API_KEY` |
| ตรวจภาษาของข้อความ **พิมพ์** | Google Cloud Translation v2 (`/detect`) | `GOOGLE_API_KEY` |
| กำกับพินอินให้คำแปลภาษาจีน | แพ็กเกจ `pinyin` (ทำงานในเครื่อง) | — |

ภาษาไหนไปทางไหนกำหนดไว้ที่ฟิลด์ `provider` ใน `src/languages.js` ที่เดียว —
`src/services/translate.js` เป็นแค่ตัวส่งต่อไปยังเจ้าที่ถูก การเพิ่มภาษาใหม่
หรือย้ายภาษาเดิมไปอีกเจ้าจึงแก้ที่ตารางเดียวโดยไม่ต้องแตะ handler

ผู้ให้บริการถูกเลือกจาก **ภาษาปลายทางที่แชทตั้งไว้** ไม่ใช่ปลายทางของคำขอแต่ละครั้ง
ดังนั้นแชทภาษาจีนจะใช้ OpenAI ทั้งขาไป (ไทย → จีน) และขากลับ (จีน → ไทย)
สำนวนที่ได้จะได้ไม่กระโดดไปมาระหว่างสองเจ้าในบทสนทนาเดียว

### ทำไมจีน/อังกฤษถึงแยกไปใช้ OpenAI

สองภาษานี้เป็นภาษาที่ LLM แปลได้เป็นธรรมชาติกว่าเครื่องแปลแบบเดิมอย่างชัดเจน
โดยเฉพาะประโยคพูดสั้นๆ ที่ไม่มีเครื่องหมายวรรคตอน ส่วนคาซัค พม่า และเวียดนาม
Google Translate ยังทำได้นิ่งกว่าและถูกกว่า จึงคงไว้ที่เดิม

`system prompt` ของฝั่ง OpenAI ย้ำหลายชั้นว่า **ให้ตอบเฉพาะข้อความที่แปลแล้ว**
ห้ามมีคำนำ คำอธิบาย หรือเครื่องหมายคำพูดครอบ เพราะผลลัพธ์ถูกเอาไปต่อเป็นข้อความ
ตอบกลับตรงๆ ถ้าโมเดลแถ `Sure, here's the translation:` มาด้วย ผู้ใช้จะเห็นในแชท
และมีชั้นเก็บกวาด (`cleanup()`) ตัดเครื่องหมายคำพูดที่ครอบทั้งก้อนออกอีกที
เผื่อโมเดลไม่ทำตามคำสั่งเป๊ะ

### พินอินกำกับคำแปลภาษาจีน

คำแปลภาษาจีนมีพินอินพร้อมวรรณยุกต์ต่อท้ายในวงเล็บ เพื่อให้ผู้ใช้คนไทยพอออกเสียง
ตามได้โดยไม่ต้องอ่านฮั่นจื้อออก:

```
你好吗？(Nǐ hǎo ma?)
ความหมาย: สบายดีไหม
```

ใช้แพ็กเกจ `pinyin` ซึ่งทำงานในเครื่องทั้งหมด จึงไม่มีคำขอเพิ่มและไม่มีค่าใช้จ่ายต่อข้อความ
ขึ้นเฉพาะทิศทาง **ไทย → จีน** เท่านั้น ขากลับจีน → ไทยผลลัพธ์เป็นภาษาไทยอยู่แล้ว
ไม่ต้องกำกับ และถ้าคำแปลไม่มีอักษรจีนเลย (เช่นเป็นตัวเลขล้วน) ก็ไม่ต่อวงเล็บให้รก

เครื่องหมายวรรคตอนเต็มความกว้างของจีนถูกแปลงเป็นแบบละตินในบรรทัดพินอิน
(`？` → `?`) และตัดช่องว่างที่ลอยอยู่หน้าเครื่องหมายออก ไม่งั้นจะได้ `Nǐ hǎo ma ?`

ภาษาอื่นไม่ต้องทำ romanization — คาซัคใช้ซีริลลิก แต่เวียดนามเขียนด้วยอักษรละติน
(Quốc Ngữ) อ่านออกเสียงได้เลยในตัว ส่วนพม่าฝั่งผู้ใช้อ่านคำแปลไทยที่บรรทัดล่างได้อยู่แล้ว

## สิทธิ์การใช้งาน

บอทเป็น **ระบบปิด** — ทุกคนที่จะใช้ได้ต้องถูกผู้ดูแลกดอนุมัติก่อน เพราะทุกข้อความ
ที่เข้ามาแปลงเป็นเงินที่เจ้าของบอทจ่ายเอง ถ้าปล่อยเปิดไว้ ใครก็ยิงบิลใส่ได้

`src/handlers/access-control.js` ถูกลงทะเบียนเป็น **middleware ตัวแรกสุด** ทุก update
จึงวิ่งผ่านที่นี่ก่อน handler อื่นทั้งหมด รวมถึง `/start` และ `/cl` ด้วย

| ผู้ส่ง | ผลลัพธ์ |
| --- | --- |
| `SUPER_ADMIN_ID` | ผ่านเสมอ ไม่ต้องอนุมัติตัวเอง |
| อยู่ใน approved list | ผ่าน |
| คนอื่น | **ไม่ถูกประมวลผลและไม่ได้รับข้อความตอบกลับใดๆ** |

คนที่ยังไม่ได้รับอนุญาตจะเจอบอทเงียบสนิท ไม่มีข้อความบอกว่า "คุณไม่มีสิทธิ์" ด้วยซ้ำ
เพื่อไม่ให้บอทกลายเป็นเครื่องมือยืนยันว่า chat id ไหนมีอยู่จริง

### การขออนุมัติ

ครั้งแรกที่คนใหม่ทักมา ผู้ดูแลจะได้ข้อความแจ้งพร้อมปุ่ม `✅ อนุมัติ <ชื่อ>` กดแล้ว
คนนั้นใช้บอทได้ทันทีและได้รับข้อความแจ้งกลับไปว่าอนุมัติแล้ว

การแจ้งเตือนเกิด **ครั้งเดียวต่อคน** ไม่ใช่ทุกข้อความ ตัวกันแจ้งซ้ำคือคิว `pending`
ในไฟล์ ไม่ใช่ตัวแปรในหน่วยความจำ ผู้ดูแลจึงไม่โดนสแปมแม้บอทจะรีสตาร์ทไปหลายรอบ
คิวนี้ยังทำหน้าที่จำชื่อผู้ใช้ไว้ให้ปุ่มอนุมัติด้วย เพราะ callback data ของ Telegram
ใส่ได้แค่ chat id

### เมนูผู้ดูแล

พิมพ์ `/start` ในฐานะผู้ดูแลจะได้ปุ่มเพิ่มสองปุ่ม:

- **👥 จัดการ user** — รายชื่อผู้ใช้ที่อนุมัติแล้วเป็นปุ่ม กดชื่อไหนคือจะถอนสิทธิ์คนนั้น
  มีด่านยืนยันอีกชั้นก่อนลบจริง กันนิ้วลั่น
- **📊 เช็คค่าใช้จ่ายเดือนนี้** — รายงานข้อความธรรมดา เรียงจากคนที่ใช้หนักที่สุด

ทุกปุ่มตรวจสิทธิ์ซ้ำในตัวเอง ไม่พึ่ง middleware อย่างเดียว เพราะ middleware ปล่อย
ผู้ใช้ที่อนุมัติแล้วทุกคนผ่าน — ซึ่งยิง callback data เองได้ถ้าอยากลอง

## ค่าใช้จ่าย

`src/services/usage-tracker.js` จดปริมาณการใช้ทุกครั้งที่ยิง API ที่มีค่าใช้จ่าย:
การถอดเสียงคิดตาม**ความยาวคลิปเป็นวินาที** ส่วนการแปลคิดตาม**จำนวนตัวอักษร**
แยกตามผู้ให้บริการ รวมยอดโดยใช้ `chat_id` เป็นคีย์

เก็บแยกไฟล์ตามเดือน (`data/usage-YYYY-MM.json`) เพราะรายงานที่ใช้จริงคือเดือนปัจจุบัน
ไฟล์เดือนเก่าจึงไม่ถูกอ่านหรือเขียนซ้ำอีก และเก็บไว้เป็นประวัติได้โดยไฟล์ปัจจุบันไม่โตขึ้นเรื่อยๆ

ไฟล์เก็บแค่ **ปริมาณ** ไม่เก็บยอดเงิน — ค่าใช้จ่ายถูกคิดตอนเปิดรายงานโดยใช้อัตราใน
`config/api-rates.js` ปรับราคาที่นั่นแล้วรายงานย้อนหลังคิดด้วยราคาใหม่ทันที

> ตัวเลขที่ได้เป็นการประมาณจากราคาป้าย **ไม่ได้หัก free tier** และไม่ใช่ยอดบิลจริง
> ฝั่ง OpenAI ยังต้องเดาอัตราแลกตัวอักษรเป็นโทเคนอีกชั้น (ดูที่มาของตัวเลขได้ใน
> คอมเมนต์ของ `config/api-rates.js`) ใช้เทียบกันระหว่างผู้ใช้ว่าใครใช้หนักกว่าใครได้
> แต่อย่าเอาไปกระทบยอดกับบิลจริง

การจดปริมาณไม่ทำให้การแปลล้มเหลว — เขียนไฟล์ไม่ผ่านก็แค่ log แล้วผู้ใช้ยังได้คำแปลตามปกติ

## การทำงาน

**ขาไป — ผู้ใช้ส่งข้อความเสียงภาษาไทย**

1. บอท react ข้อความเสียงด้วย ❤ ทันที เป็นการบอกว่าได้รับแล้วโดยไม่ต้องรอผลแปล
2. ครั้งแรกของแต่ละแชท บอทจะถามภาษาปลายทางด้วยปุ่ม
   🇰🇿 คาซัค | 🇬🇧 อังกฤษ | 🇨🇳 จีน | 🇲🇲 พม่า | 🇻🇳 เวียดนาม แล้วจำไว้ต่อ `chat_id`
3. ดาวน์โหลดไฟล์เสียงจาก Telegram → ส่งเข้า Speech-to-Text → ได้ข้อความ + ภาษาที่ตรวจได้
4. ส่งข้อความเข้าผู้ให้บริการแปลของแชทนั้น → ตอบกลับ 2 บรรทัด

```
Сәлеметсіз бе
ความหมาย: สวัสดีครับ สบายดีไหม
```

บรรทัด `ความหมาย:` คือ transcript ภาษาไทยจากการถอดเสียงโดยตรง ไม่ได้เรียก AI เพิ่ม
และรูปแบบนี้เหมือนกันทุกภาษา ไม่ว่าคำแปลจะมาจาก Google หรือ OpenAI

**ขากลับ — อีกฝ่ายตอบกลับมา**

ทุกข้อความที่เข้ามา (พิมพ์หรือเสียง) จะถูกตรวจภาษา ถ้าตรงกับภาษาปลายทางที่ตั้งไว้
บอทจะแปลกลับเป็นไทยให้อัตโนมัติ

### ตรวจภาษาโดยไม่ต้องเดาทิศทาง

ไฟล์เสียงไม่ได้ถูกล็อกเป็นภาษาไทย — คำขอถอดเสียงตั้ง `languageCode` เป็น `th-TH`
เป็นหลัก แล้วใส่ภาษาปลายทางของแชทลง `alternativeLanguageCodes` ทำให้ Google
ตรวจให้เองว่าเสียงนี้เป็นภาษาไหนในสองภาษานั้น แล้วคืน `languageCode` มากับผลถอดเสียง
ในคำขอเดียวกัน

รหัสที่ฝั่ง Speech ใช้ไม่เหมือนฝั่ง Translation (จีนกลางตัวย่อคือ `cmn-Hans-CN`
ไม่ใช่ `zh-CN`) และ Google คืนกลับมาเป็นตัวพิมพ์เล็กทั้งหมด `fromSpeechCode()`
ใน `src/languages.js` จึงแปลงกลับเป็นรหัสภายในของบอทให้ก่อนใช้ตัดสินทิศทาง

ผลคือรู้ภาษาต้นทางแน่นอนตั้งแต่ก่อนแปล จึงระบุ `source` ให้ผู้ให้บริการแปลได้ตรงๆ
และแปลแค่ครั้งเดียวต่อข้อความเสมอ — เดิมบอทเดาทิศทางจากช่องทางที่ข้อความเข้ามา
แล้วต้องยิงแปลซ้ำอีกทางเมื่อเดาผิด ตอนนี้ไม่มีกรณีนั้นแล้ว

| ข้อความเข้ามา | คำขอที่ใช้ |
| --- | --- |
| เสียงภาษาไทย | ถอดเสียง 1 + แปล 1 |
| เสียงภาษาปลายทาง | ถอดเสียง 1 + แปล 1 |
| พิมพ์ภาษาปลายทาง | ตรวจภาษา 1 + แปล 1 |
| พิมพ์ภาษาไทย (เงียบ) | ตรวจภาษา 1 |

ข้อความ **พิมพ์** ไม่มีขั้นตอนถอดเสียงให้อาศัย จึงยิง `/detect` ของ Google ก่อนหนึ่งครั้ง
(ไม่ว่าแชทนั้นจะแปลด้วยเจ้าไหน) แลกกับการที่ทั้งสองเส้นทางเดินโค้ดชุดเดียวกัน
และภาษาที่ตรวจได้ยังถูกเขียนลง log ทุกครั้งพร้อมชื่อผู้ให้บริการที่ใช้ เพื่อให้ไล่ปัญหาได้

ข้อความ **พิมพ์** ภาษาไทยจะถูกปล่อยผ่านเงียบๆ เพื่อไม่ให้บอทตอบแทรกทุกประโยค
ที่คนไทยคุยกันในแชท — การแปลขาไปเริ่มจากข้อความเสียงเท่านั้น

## ความเร็วและความเสถียร

ระหว่างประมวลผลข้อความเสียง บอทจะขึ้นสถานะ "กำลังพิมพ์" ทันทีหลัง react ❤
แล้วส่งซ้ำทุก 4 วินาทีจนกว่าจะตอบกลับ เพราะ Telegram ให้สถานะหมดอายุเองที่ราว 5 วินาที
งานที่ใช้เวลานานกว่านั้นจึงต้องต่ออายุเอง ไม่งั้นแชทจะดูเงียบทั้งที่บอทยังทำงานอยู่

ทุกการยิง API (ดาวน์โหลดไฟล์เสียง, Speech-to-Text, Google Translate, OpenAI)
จะ**ลองใหม่อัตโนมัติ 1 ครั้ง** เมื่อเจอ timeout หรือปัญหาเครือข่าย (`ECONNRESET`,
`ECONNREFUSED`, ฯลฯ) โดยหน่วง 1 วินาทีก่อนลอง ส่วนกรณีที่ API ตอบกลับมาแล้ว
ด้วยสถานะผิดพลาด (4xx/5xx) จะไม่ลองซ้ำ เพราะยิงใหม่ก็ได้คำตอบเดิม เสียเวลาผู้ใช้เปล่าๆ

| ค่า | ปัจจุบัน |
| --- | --- |
| timeout ของ Speech-to-Text | 60 วินาที |
| timeout ของ OpenAI | 30 วินาที |
| timeout ของ Google Translate | 15 วินาที |
| timeout ของการดาวน์โหลดไฟล์เสียง | 30 วินาที |
| จำนวนครั้งที่ยิงรวม | 2 (ครั้งแรก + ลองใหม่ 1) |

`speech:recognize` เป็น endpoint แบบ synchronous ซึ่งรับเสียงยาวได้ไม่เกิน 1 นาที
ข้อความเสียงในแชทสั้นกว่านั้นเกือบทั้งหมด ถ้าอนาคตต้องรองรับเสียงยาวกว่านี้
ต้องย้ายไป `longrunningrecognize` ซึ่งต้องอัปโหลดขึ้น Cloud Storage ก่อน

หากล้มเหลวจนครบทุกครั้ง บอทจะตอบว่า
`ขออภัย เกิดข้อผิดพลาดในการแปล ลองใหม่อีกครั้ง` และเขียน error ลง log แทนการ crash

## การติดตั้งและใช้งาน

ต้องใช้ Node.js เวอร์ชัน 18 ขึ้นไป

```bash
# 1. ติดตั้ง dependencies
npm install

# 2. สร้างไฟล์ .env จากตัวอย่าง
cp .env.example .env

# 3. ใส่ token ที่ได้จาก @BotFather ลงในไฟล์ .env
#    TELEGRAM_BOT_TOKEN=123456:ABC-DEF...

# 4. รันบอท
npm start
```

ระหว่างพัฒนาใช้ `npm run dev` เพื่อให้ Node รีสตาร์ทอัตโนมัติเมื่อไฟล์เปลี่ยน

## การทดสอบ

```bash
npm test
```

ใช้ test runner ที่มากับ Node (`node:test`) จึงไม่ต้องลง dependency เพิ่ม
ทุกเทสต์สลับ `global.fetch` เป็นตัวปลอมที่จ่ายคำตอบตาม URL — ไม่มีการยิงเน็ตจริง
ไม่ต้องใช้ API key จริง และไม่แตะไฟล์ใน `data/`

ครอบคลุม: คำขอถอดเสียงตรงตามฟอร์แมตของ Telegram, ตรวจภาษาถูกทั้งสองทิศทาง,
คาซัค/พม่า/เวียดนามวิ่งไป Google ส่วนจีน/อังกฤษวิ่งไป OpenAI (ทั้งขาไปและขากลับ),
พินอินขึ้นเฉพาะทิศทางไทย → จีน, ปุ่มเลือกภาษาครบทุกภาษาในตาราง,
รูปแบบข้อความตอบกลับเหมือนกันทุกผู้ให้บริการ, `system prompt` สั่งให้ตอบเฉพาะคำแปล,
การตัดเครื่องหมายคำพูดที่ครอบผลลัพธ์, การลองใหม่เมื่อเน็ตสะดุด, การไม่ลองซ้ำเมื่อ
API ตอบสถานะผิดพลาด, ข้อความแจ้งข้อผิดพลาด และสถานะ "กำลังพิมพ์"

ฝั่งสิทธิ์และค่าใช้จ่าย: คนแปลกหน้าไม่ถูกประมวลผลและไม่ได้รับคำตอบ (รวมถึงตอนใช้ `/cl`),
ผู้ดูแลได้รับแจ้งครั้งเดียวพร้อมปุ่มอนุมัติ, กดอนุมัติแล้วใช้งานได้ทันที, การถอนสิทธิ์
ผ่านด่านยืนยัน, ผู้ใช้ทั่วไปยิง callback ของผู้ดูแลไม่ได้, และการสะสมปริมาณกับการคิดเงิน
แยกตามชนิดการเรียกและแยกเดือน

ชุดทดสอบตั้ง `DATA_DIR` เป็นโฟลเดอร์ชั่วคราวของตัวเอง จึงไม่แตะไฟล์ใน `data/` ของจริง

## ตัวแปรสภาพแวดล้อม

| ตัวแปร | จำเป็น | คำอธิบาย |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | ✅ | Token ของบอทจาก [@BotFather](https://t.me/BotFather) |
| `SUPER_ADMIN_ID` | ✅ | Telegram ID (ตัวเลข) ของผู้ดูแล — คนเดียวที่อนุมัติผู้ใช้และดูค่าใช้จ่ายได้ |
| `GOOGLE_API_KEY` | ✅ | Google Cloud — Speech-to-Text (ถอดเสียง) + Translation v2 (แปลคาซัค/พม่า/เวียดนาม, ตรวจภาษา) |
| `OPENAI_API_KEY` | ✅ | OpenAI — ใช้แปลภาษาจีนและอังกฤษ |

`GOOGLE_API_KEY` ตัวเดียวใช้กับทั้งสองบริการได้ ขอแค่เปิด **Cloud Speech-to-Text API**
และ **Cloud Translation API** ไว้ในโปรเจกต์เดียวกัน

ถ้าไม่มี `TELEGRAM_BOT_TOKEN` บอทจะหยุดทำงานทันทีพร้อมข้อความบอกวิธีตั้งค่า
ส่วนตัวอื่นถ้าไม่มีบอทยังเริ่มได้แต่จะเตือนใน log และฟีเจอร์ที่เกี่ยวข้องจะตอบว่า
เกิดข้อผิดพลาด — ยกเว้น `SUPER_ADMIN_ID` ที่ถ้าไม่ตั้ง จะไม่มีใครอนุมัติใครได้เลย
บอทก็จะเงียบกับทุกคน

ตั้ง `DATA_DIR` เพิ่มได้ถ้าอยากย้ายที่เก็บไฟล์ข้อมูลออกจากโฟลเดอร์ `data/` ข้างโปรเจกต์

## ความปลอดภัย

- **ห้าม** commit ไฟล์ `.env` หรือใส่ token / API key จริงลงในโค้ดเด็ดขาด
- `.gitignore` กัน `.env` และ `node_modules/` ไว้แล้ว
- หาก token หลุดออกไป ให้ revoke ทันทีผ่าน `/revoke` ที่ @BotFather
- API key ของ Google ควรจำกัดสิทธิ์ให้เรียกได้เฉพาะสองบริการที่ใช้จริง
